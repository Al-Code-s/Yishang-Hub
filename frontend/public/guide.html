2.2 暂时还没有的（不要按「能用」去承诺）#

  • 生产执行（MES）暂时没有的：线体排产与产能冲突检查、裁剪任务 / 裁片批次、工位派工与接单、在制品转移与独立的返工工单、扫码 / RFID 与硬件控制、工序良率与 OEE、工单成本。工单与报工本身已可用（见 6.13）。
  • 质量管理（QMS）暂时没有的：检验标准的版本快照（改标准不会回写历史单据）、返工 / 报废处置工单、检测仪器直连自动取数。检验结果目前一律人工录入，平台只负责按标准判定与留痕。另外采购收货单上的「来料检验放行」仍是独立的人工判定，还没有改成引用检验单。
  • MQTT / Modbus 等工业协议与真实设备直连：平台已支持设备通过 HTTP 上报采集数据（并内置模拟器可用于演示），但把电表 / PLC / DCS 直接接入采集网关、按 MQTT / Modbus 实时取数尚未实现，需要先确认设备协议。能源数据目前仍以人工抄表为主，数采读数不会混入抄表数据。
  • 设备远程控制（开关机、参数下发、安全联锁）：平台只做只读采集，不下发任何控制指令，也不替代 PLC 实时控制、安全联锁或消防联动。
  • 工业终端安全。
  • 销售计划与预测、供应商寻源 / 报价、应收应付与收付款登记、跨仓调拨在途、盘点范围冻结、库存成本。
  • MRP 目前不包含：采购提前期与批量规则、安全库存、替代料展开、销售订单以外的需求来源、MRP 导出与定时重算。（在制供给与生产建议转单已可用，见 6.13）

容易误会的地方实际情况

三、登录与账号#

3.1 登录#

  1. 打开平台地址（由实施人员提供），未登录时会自动进入登录页。
  2. 输入用户名与口令，点「登录」。
  3. 登录成功后进入你菜单里的第一个页面（通常是「工作台」）。
  • 直接访问站点根路径也会跳到同一页，不会出现「顶栏有标题、内容区却空白」的情况；
  • 如果你没有「工作台」的查看权限，会自动落到你第一个可访问的页面；
  • 平台部署在公司内网：同一局域网内的其他电脑用同一个地址就能打开，不需要各自安装任何软件。

3.2 登录不上怎么办#

现象原因与处理
提示「用户名或口令错误」核对大小写与输入法；系统不区分「账号不存在」与「口令错误」，避免账号被探测
提示账号被锁定连续输错次数过多触发临时锁定。等待解锁窗口后再试，或联系管理员解锁
提示尝试过于频繁同一来源短时间内登录次数过多，稍等片刻再试
提示账号已停用账号被管理员停用，联系管理员
一直停留或跳回登录页会话可能已过期，重新登录即可；仍不行请联系实施人员
局域网内其他电脑打不开核对地址是否输全（端口不是 80 时必须带端口，如 http://192.168.1.49:8080/）；确认与服务器在同一个局域网；仍不通请联系实施人员检查防火墙放行与访问白名单

3.3 修改密码#

  • 右上角个人中心 → 修改密码：填写原口令与新口令即可。
  • 用初始口令首次登录时，页面顶部会提示尽快修改密码，请及时处理。
  • 管理员重置口令后，下次登录同样会收到修改密码提示。
  • 口令由本人保管；平台不会以任何形式向使用者索取口令。

四、界面导航与通用操作#

4.1 界面结构#

  • 左侧导航：一级是目录（工作台、基础资料、工厂与排班、客户管理、销售管理、供应商管理、采购管理、计划管理、仓储管理、审批中心、内部协同、系统管理），二级是具体页面；一级与二级在样式上有明显层级区分（缩进、字号、分组底色）。
  • 顶部工具栏：折叠侧边栏、面包屑、使用说明、刷新当前页面数据、通知入口、个人中心。面包屑显示当前页面在菜单里的层级，例如「基础资料 / 物料档案」。
  • 多标签页：打开过的页面会留在顶部标签里，可来回切换，也可以关闭标签。
  • 窄屏自适应：窗口较窄时侧边栏自动折叠（你的手动偏好优先），表格在容器内横向滚动。
  • 菜单按权限下发：没有权限的页面不会出现在菜单里，也没有对应地址。

5.2 为什么有的菜单和按钮看不到#

平台用四层权限控制「能看到什么、能做什么」：

层作用表现
菜单权限决定左侧是否出现该页面没有权限时菜单不显示，也没有对应地址（不是「点进去才报错」）
操作权限决定按钮 / 动作能否执行例如没有「运行 MRP」权限时，该动作会被拒绝
接口权限每一次后台调用都会重新校验界面上藏起来的按钮不等于后台放行
数据范围限制「能看哪些数据」公司 / 指定工厂 / 指定部门 / 指定仓库 / 本人 / 自定义范围
  • 一个人有多个角色时：操作权限取并集，数据范围取最宽一档，但始终先受公司边界限制；范围配置不完整时按最小范围处理（宁可看不到，也不越界）。
  • 超级管理员不受数据范围限制。

5.4 新增用户与分配权限#

  1. 「系统管理 → 用户管理」→ 新建用户（用户名、姓名、所属公司 / 部门、初始口令）。
  2. 「系统管理 → 角色权限」→ 选角色 → 勾选权限点；需要限制可看的数据时再配置「数据范围」。 - 权限树的一级分组显示为「英文模块（中文名）· 权限点数」，例如 core（公共基础）· 12 项，照着左侧菜单的业务名找对应分组即可。
  3. 把角色分配给用户（用户管理里的角色多选）。
  4. 用新账号登录验证：能看到的菜单应与勾选的权限一致；看不到就是没有勾。

平台的第一个管理员账号由实施人员初始化时创建（默认用户名 admin，口令由实施人员设定）。 该账号不隶属任何公司，因此新建需要公司维度的数据时要显式选择「公司」； 提示「缺少公司标识」是刻意的设计，不是故障。

六、按模块操作指南#

所有模块都遵循同一套顺序：列表页 → 新建 / 详情 → 提交 → 审批 → 后续动作。 关键规则由系统在后台执行，界面只是入口。

6.1 基础资料（物料 / 款式 / 颜色 / 尺码 / SKU / 单位）#

  1. 先建物料分类（面料 / 辅料 / 半成品 / 成品 / 包装物 / 备品备件 / 消耗品）。
  2. 建计量单位与换算规则（如 米 ↔ 公斤、打 ↔ 件）；面料「米」与「公斤」不无条件换算，若因卷而异，按实际计量值与该卷的换算依据保存。
  3. 建物料：编码、名称、规格、基本单位、采购 / 销售辅助单位、是否批次管理、安全库存、采购价与参考成本、启停状态；面料物料另填成分、幅宽、克重、色号等。
  4. 建颜色与尺码，再建款式（SPU），最后按「款式 + 颜色 + 尺码」生成 SKU。成品 SKU 与库存物料是一对一的，不存在两套库存编码。
  5. 标识分型要区分清楚：SKU 条码（识别物料种类）、批次码、卷号、箱码、RFID EPC、载具码 ——它们不能混用一个字段。

6.2 工厂与排班#

  • 公司 → 部门（树形）→ 工厂 → 车间 → 线体 → 工位；员工、班组、班次、排班日历。
  • 已使用的组织只能停用不能删除；层级关系不合法会被拒绝。
  • 班次支持跨夜、休息、节假日与调班；排班展开为人员执行记录时会保留成员快照。

6.4 采购#

采购申请(draft) → 提交 → 审批 → approved → 转采购订单(draft) → 提交 → 审批 → approved
   → 收货单(draft) → 过账 → 库存进入「待检」 → 来料检验(合格/不合格) → 合格库存
  • 不允许超收：可收上限 = 订单行数量 − 已收 − 草稿占用；订单状态随收货推进 approved → partially_received → received，未收完可以「关闭」。
  • 实物到货、库存记账、质量放行是三件事：到货 ≠ 可入库，入库 ≠ 可放行。
  • 来料检验目前是人工录入判定（未接入检测设备），判定人、结论、说明与依据单据一并留痕。
  • 供应商被停用后不能建正常采购订单；特殊情况需要显式授权。

6.5 销售#

销售订单(draft) → 提交 → 审批 → approved → 库存占用(reserve)
   → 发货单(draft) → 过账 → 合格库存出库 → 订单行已发数量
   → 销售退货(draft) → 过账 → 库存进入「待检」 → 检验判定 → 合格 / 不合格
  • 必须先占用才能发货（未占用直接发货会被拒绝），且不能挪用其他订单的占用。
  • 发货上限 = 订单行数量 − 已发货；可退数量 = 已发货 − 已退货，超出会被拒绝。
  • 退货行未填储位 / 批次 / 卷号时，会继承原发货单据的维度并写回退货行，保证批次追溯不断链。
  • 订单详情提供链路查询：从订单查看关联的占用、发货、退货与库存单据。
  • 收款登记不等于完整财务记账（应收 / 收付款属后续增量）。

6.6 计划：BOM 与工艺路线#

  • BOM：一个「款式 + SKU 范围」可以有多个版本，但同一时间只有一个已审核版本生效；审核新版本时旧版本自动转「已作废」。明细含标准用量、损耗率（系统算出含损耗用量）、替代料（必须指向同一张 BOM 的正常用料行）、使用部位、是否关键用料。
  • 工艺路线：工序顺序、工作中心 / 线体、设备要求、标准工时、是否工序质检点；新建时默认给出「裁剪 → 缝制 → 整烫 → 检验 → 包装」。
  • 改动方式：只能「派生新版本」，已审核版本不可就地修改（下游单据引用的内容必须不变）；作废需填写原因。

6.7 MRP（计划管理 → MRP 运算 / 缺料与建议）#

操作顺序

  1. 「MRP 运算」→ 选公司（管理员必须选）→ 填需求区间（默认今天起 90 天）→ 选按日 / 按周 → 可选限定仓库 → 「运行 MRP」。系统立即计算并返回结果与摘要。
  2. 打开该运行的详情，看三个页签：需求行（含来源与分段）、供给行（可用库存 / 采购在途）、 缺料建议。
  3. 「缺料与建议」→ 对采购建议点「转采购申请」（填需求日期）→ 生成草稿采购申请并显示单号；对生产建议点转单 → 生成草稿生产工单（不会自动下达，下达仍到「生产执行 → 生产工单」操作）。
  4. 不需要的建议可以「取消」（必填原因）；历史运行可以「归档」（归档后其建议不能再转单）。

口径（重要）

项当前口径
需求来源只有销售订单（已批准、未发货的剩余数量）
供给可用库存（实存 − 冻结 − 占用，且只认合格质量状态）+ 采购未收货在途 + 在制供给
在制供给已下达 / 生产中工单的未完工数量；草稿工单不算（避免把还不存在的产能当成供给）
展开用量取 BOM 的含损耗用量；只展正常用料行，替代料不参与
批量规则净需求多少建议多少（lot-for-lot），无提前期、无安全库存缓冲
净算方式按低层码分层，同一物料只净算一次；父件按净需求展开子件
生产建议转单只生成草稿生产工单，不自动下达（下达会冻结快照并生成工序，需生产角色确认）
转单结果采购建议 → 草稿采购申请（仍需走采购审批）；生产建议 → 草稿生产工单。两者都写入单据关联

运行结果示例（演示环境）：历史运行 MRP202609180004 的摘要为 item_count=7 / level_count=2 / bucket_count=3 / demand_quantity=1422.300000 / supply_quantity=1866.000000 / suggestion_count=5（1 条生产建议 + 4 条采购建议），其中 SO-MRP-0001（成品 300 件）展开出 5 条子件需求。

6.8 审批中心#

  • 「我的待办」处理需要自己审批的节点；「我的申请」看自己提交的单据与进度；「审批模板」维护流程。
  • 模板支持顺序多级与条件路由（按金额区间、部门匹配审批人）；单据提交时会保存模板快照，模板后续修改不影响在途单据。
  • 动作：提交 / 通过 / 驳回（必填意见）/ 撤回；每次动作都会写审批轨迹（只写不改）。
  • 可以限制「申请人审批自己的单据」（模板开关）。
  • 审批通过与库存过账是两个不同动作，互不代表。

6.9 内部协同与系统管理#

页面用途
事件与协同查看跨模块业务事件的处理状态（待处理 / 处理中 / 已完成 / 失败待重试 / 需人工处理）、失败原因与人工重放；单据关系追溯
用户管理 / 角色权限 / 权限与菜单账号、角色、权限点、菜单与数据范围
数据字典 / 编码规则枚举值与单号规则（支持编号预演）

我的通知审批、告警等通知

表格里的「业务对象」「对象编号」「事件编号」都是排查问题时用的业务标识：「业务对象」显示中文名称（如「销售订单」），不会出现程序内部的写法；「事件编号」是系统内部的事件编码，管理员定位失败原因时需要用到。

如果事件长时间停在「待处理」，通常是后台任务没有运行， 请通知实施人员确认；这不影响单据状态与业务结果。

6.10 客户投诉与产品评价#

页面用途与动作
客户投诉登记投诉（客户、类型、级别、来源、内容）→ 点「受理」记下受理人 → 点「处理」必须填写处理措施 → 点「关闭」；关闭后可登记满意度（0 表示未评价，1~5 为评分）
产品评价登记评价（客户、产品、评分 1~5、评价内容）→ 点「回复」填写官方回复 → 点「关闭」
  • 投诉与评价的状态不能直接改，只能通过上面的动作按钮推进；跳步会被拒绝（例如未受理就想关闭）。
  • 每一步流转都会写进审计日志，便于回看「谁在什么时候处理了什么」。

顶部统计怎么看

  • 页面顶部有统计卡片：投诉看「总数 / 未关闭 / 平均满意度」，评价看「总数 / 待回复 / 平均评分 / 好评率」。
  • 卡片下方是分布表：投诉按处理状态、投诉类型、投诉级别、投诉来源分布；评价按 1~5 分各档分布（含各档占比）。
  • 统计是按当前条件实时算出来的：筛选、推进状态、补录满意度之后数字立刻跟着变，随时能回到列表逐条核对。
  • 没有回访就没有满意度：范围内一条都没评过时，平均满意度显示「未回访」，不会用 0 分把平均值拉低；未评价的条数单独显示，便于催办。
  • 好评率按「4 分及以上」计算，分母是该范围内的全部评价。

6.11 设备数采与监控#

页面用途
数采连接配置登记数据从哪里来：协议（当前支持 HTTP 上报与内置模拟器）、接入地址、单次上报测点上限、每分钟上报上限、凭证引用
数采设备登记采集单元（网关 / 传感器 / 智能水表 / 智能电表）及其归属；点「生成令牌」把令牌下发到设备侧
采集测点登记设备上的具体物理量（温度 / 电压 / 电流 / 振动 / 流量等）、单位、精度与报警上下限
设备监控按设备看在线状态、各测点最新读数与「超限」提示、近 24 小时的读数与失败报文数量
采集读数设备上报的标准读数（只读），可按设备、测点、质量与来源筛选
采集日志每一次上报的原始报文与处理结果，包含重复报文与处理失败报文（只读）
采集统计（在「设备监控」页下方）按测点与时间桶汇总读数：可切换按小时 / 按天，查看样本数、覆盖测点、越限时间桶与读数合计，以及每个「时间桶 × 测点」的最小 / 最大 / 平均值

使用要点

  • 设备令牌只显示一次：点「生成令牌 / 轮换令牌」后，令牌明文只在弹出的窗口里出现一次，请立即写入设备侧并妥善保存；窗口关闭后只能重新轮换。轮换后旧令牌立即失效。
  • 设备按下面的格式向平台上报（请求头带 X-Device-Token）：
  POST /api/v1/iot/ingest/
  X-Device-Token: <设备令牌>
  {
    "message_id": "设备侧生成的唯一消息号",
    "device_time": "2026-09-21T10:00:00+08:00",
    "points": [{"code": "测点编码", "value": "23.50"}]
  }
  • 重复上报不会重复入账：同一个消息号只入账一次（重复的记入采集日志）；同一测点同一设备时间的读数也只保留一条。
  • 越限与离线会自动报警：测点读数越过报警上下限、或设备超过「离线判定」时长没有上报，都会在「能源管理 → 报警管理」里生成报警，处理方式与能源报警一致。
  • 模拟数据全程带「模拟」标识：内置模拟器生成的数据在设备、读数、报文上都标注「模拟」，模拟设备不参与离线判定，也不计入真实产量与能耗。
  • 采集统计按北京时间分桶：同一台设备在同一天（北京时间）的读数会归到同一个「天」里，不会因为服务器时区被算到前一天。
  • 统计与明细是同一份数据：统计是拿「采集读数」实时算出来的，读数一变化统计立刻跟着变，页面上的数字随时能回到明细逐条核对。
  • 统计里的「越限」只是标记：它表示该时间桶内有读数越过报警上下限；正式报警仍然只在「能源管理 → 报警管理」里产生，同一份数据不会重复报警。
  • 查询范围有上限：按小时最多可查约 31 天，按天最多约 3 年（1096 天）；超出会提示区间过宽，请缩小范围。
  • 「读数合计」对累计型测点（如电表读数）才有物理含义，其余测点只能当参考。

6.12 质量管理#

页面用途与动作
检验项目先把「按什么标准检」登记好：项目编码、类别、单位、检验方法与标准要求；定量项目填标准下限 / 上限（包含端点，留空表示这一侧不设限），定性项目（如外观、手感）不填数值
检验单登记一次检验：检验类型、来源单据号、受检物料 / 批次 / 供应商 / 车间 / 设备、受检数量与抽样数量；然后录入检验结果，走「提交 → 判定 → 关闭」
质量报警检验单判定为「不合格」时系统自动生成报警；处理链路为「开始处理 → 关闭」，关闭必须写处理说明
质量问题知识库把「这一次为什么不合格」记下来：问题现象（必填）、原因分析、纠正措施、预防措施；从报警页可直接「沉淀知识库」，生成草稿后补充再发布

检验单怎么走

  1. 新建检验单（检验单号留空时由系统按规则自动生成），填写受检对象与数量。
  2. 点「录入结果」→ 逐行选择检验项目并填写结果： - 定量项目（有上下限的项目）只要填「实测值」，合格与否由系统按标准区间判定，界面不提供结论输入； - 定性项目要由检验员给出「合格 / 不合格」，并可填写实测描述（例如「色差偏深」）。
  3. 点「提交」。没有录入任何检验结果时提交会被拒绝。
  4. 点「判定」选择结论：合格 / 不合格 / 让步接收（也可以留空，由系统按检验结果自动给结论）。 - 只要存在不合格项，判「合格」会被拒绝；全部合格时判「不合格」也会被拒绝； - 判「让步接收」必须填写判定说明（原因与放行条件）。 - 判定为「不合格」时，系统自动生成一条质量报警。
  5. 点「关闭」结束这张单。该单的不合格报警还没关闭时，检验单关不掉——先处理报警再关单。

规则与提醒

  • 状态不能直接改：草稿 → 已提交 → 已判定 → 已关闭，只能通过上面的按钮推进，跳步（例如草稿直接判定）会被拒绝。
  • 判定之后不能再改结果：需要修改请新建一张检验单，历史结论不会被覆盖。
  • 同一次检验只报警一次：一张检验单无论判定几次，只生成一条质量报警；报警级别按不合格项数量自动分级。
  • 报警关闭必须写处理说明，否则不允许关闭。
  • 过时的知识库条目请「归档」而不是删除，历史结论与来源单据都能追溯。
  • 「沉淀知识库」生成的条目是草稿状态，补充完善后再点「发布」才会正式入库；已发布的条目不能再发布。

质量动态监测怎么看（检验单页面顶部）

  • 单据量（草稿 / 已提交 / 已判定）、合格率、判定分布，以及不合格项目排行（哪一类检验项目最容易出问题）。
  • 合格率只统计已判定的单据：草稿和已提交未判定的单据不计入分母，否则「还没检验」会被算成不合格，合格率凭空变低。
  • 「让步接收」单列显示，既不并入合格也不并入不合格。
  • 数字是按检验单与检验结果实时算出来的，补录结果或重新判定后立刻跟着变，随时能回到列表逐条核对。

6.13 生产执行（生产工单 / 生产报工）#

一次生产任务怎么走完

  1. 「生产执行 → 生产工单」→ 「新增」：选公司与款式，填计划数量，选车间 / 线体、领料仓库与完工入库仓库，填计划开工 / 完工时间 → 保存为草稿。工单号由系统自动生成（MO 开头），不用手工填。
  2. （可选）草稿阶段可手工维护用料；如果款式有生效的 BOM，下达时会自动按 BOM 展开，无需手工录入。
  3. 点「下达」：系统在这一刻冻结工艺路线与 BOM 快照，并据此生成工序与用料。 - 没有生效的工艺路线 → 提示 ROUTING_REQUIRED； - 既没有生效 BOM 也没有手工用料 → 提示 BOM_REQUIRED。 - 下达之后表头不能再改（数量、排期等），要改请新建工单。
  4. 点「领料」：按用料行的待领数量生成一张出库单并过账，库存相应减少。已经领过的工单再点会被拒绝；重试请带幂等键（见下）。
  5. 点「报工」：选工序，填报工数量，再填其中的合格 / 返工 / 报废数量与实际工时。 - 三个数相加必须正好等于报工数量，否则提示 QUANTITY_MISMATCH； - 同一工序累计报工不能超过计划数量，超了提示 OVER_PRODUCTION； - 报工是原始记录，不能修改：填错了请补一条返工报工，不要把历史数字改掉。
  6. 质检点工序报满（累计报工达到计划数量）时，系统自动开一张检验单到「质量管理 → 检验单」，需判为「合格」或「让步接收」；判「不合格」或还没判定，工单都不能完工（提示 QUALITY_GATE_NOT_PASSED）。
  7. 全部工序完成后点「完工」；再点「完工入库」把末道工序的累计合格数入到入库仓库。入库经统一库存服务过账，重复入库会被拒绝。
  8. 最后点「关闭」结束工单。已下达但还没开工的工单如果不再需要，可以「取消」（必须填原因）； 已经开工的不能取消。

要注意的几条

  • 下达前的工单是草稿，改数量、改用料都没问题；下达后就冻结，避免生产到一半数字被改。
  • 报工单不能改也不能删，这是刻意设计：生产记录要能追溯，错了靠补报工而不是改历史。
  • 领料与入库都走统一库存服务，页面不直接改库存数字；重试请带幂等键，系统会返回第一次的结果，不会重复扣减或重复入库。
  • 质检点报满自动开单，不需要手工建检验单；但判定仍在检验单页面完成。
  • 工单详情抽屉里能直接看到用料表与工序表（含每道工序的累计报工 / 合格 / 报废）。
  • 「生产报工」页是只读台账，只能查看；报工入口在工单上。

MRP 与生产工单的关系

  • 「缺料与建议」里的生产建议可以「转生产工单」，生成的是草稿工单（不自动下达）。
  • MRP 计算时会把已下达 / 生产中工单的未完工数量当作在制供给，冲减净需求； 草稿工单不算——避免把还不存在的产能当成可用供给。

6.14 供应商评价（五维量化评价）#

第一步：配置评价权重（每个公司一份）

  1. 「供应商管理 → 评价权重配置」→「新增」：为质量、技术、响应、交付、成本五个维度填权重（百分比）。 - 五项合计必须正好等于 100，差一点都会被拒（WEIGHT_TOTAL_INVALID）； - 保存后这一版即为启用版本，同一公司同一时间只有一版启用。
  2. 需要调整权重时，在该行点「修改」再保存：系统会派生一个新版本（版本号 +1）并自动启用、同时停用旧版本。 - 旧版本不会被覆盖：过去按旧权重评过的单据，仍按当时的权重解释，这是刻意设计（只增不改）。

第二步：发起并完成一次评价

  1. 「供应商管理 → 供应商评价」→「新增」：选公司、供应商，选评价权重配置（不选则用该公司当前启用版本），填评价期间起 / 止、评价人与评价时间，选择缺数据口径（见下）→ 保存为草稿。评价单号由系统自动生成（SEV 开头），不用手工填。
  2. 点「录入评分」：五个维度必须各有一行，缺任何一行都会被拒（DIMENSION_ROWS_INCOMPLETE）。 - 原始得分填 0~100；没有数据的维度请把得分留空——留空表示「没有数据」，填 0 表示「这项就是 0 分」，两者含义完全不同； - 「评分依据」选填，建议写清事实（如「到货准时 12 批」）。 - 保存后系统按权重快照自动算加权总分；总分界面填不了，只由系统计算。

6.15 能源管理（能耗报表 / 能耗统计 / 能源看板）#

页面用途

能源看板选定一种介质后，按计量点 / 区域 / 部门 / 设备看占比与趋势

使用要点

  • 时间维度下按「介质」分行：统计口径切成日 / 月 / 年时，同一段时间里水、电、气、液是 每种一行，「介质」和「单位」都对得上（电是 kWh、气是 m³、水与液是 t）。所以选「全部介质」时，一个月会出现 4 行，这是正常的，不是重复数据。
  • 不要把不同介质的用量加在一起看：kWh、m³、t 不是同一个单位，跨介质相加没有物理意义。要看某个介质的量，请先把「介质」筛成那一种。
  • 趋势图按介质画多条线：多介质时每条线的名字后面带单位（如「电（kWh）」），可以分别读数。
  • 合计用量只是各行的算术和：它把不同单位的用量加在了一起，不能当成一个物理量使用；页面上方卡片的「合计费用」不受影响，可以正常用。
  • 未维护单价的介质，费用计 0 并标注：列表里会标「未维护单价」，需要先到「能源管理 → 基础管理」补上该介质的现价，否则费用按 0 计算。
  • 尖峰平谷报表要先选介质：不选介质时这张报表不显示（分时段单价是按介质维护的）。
  • 数值显示：用量与费用统一显示 2 位小数，导出的 Excel 也是同样口径（见 §4.2）。
