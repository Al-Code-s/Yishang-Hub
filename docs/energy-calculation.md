# 能源计量与计算（docs/energy-calculation.md）

> **状态：设计已完成，实现在阶段 5。** 阶段 0/1 尚未创建 `ems` / `iot` 模块，
> 也**不存在任何真实硬件接入**。本文件定义阶段 5 的强制计算口径。
> 在真实设备与协议确认前，不得宣称已完成采集接入。

## 一、数据链路

```text
连接配置 → 网关/设备 → 测点 → 原始消息 → 标准化读数 → 汇总/告警
```

- **原始消息与标准化读数分开存储**：原始消息保留原始报文与接收时间，标准化读数带单位与质量标记。
- 读数必带字段：设备、测点、**设备时间**与**接收时间**、数值、单位、数据质量、来源、
  消息 ID、序列号或去重依据、处理状态。
- 设备上报使用**独立设备凭证**，不复用员工会话；入口做**限流与批次大小限制**。

## 二、计量规则（强制）

1. **区分瞬时值与累计值**。累计值（表底数）**通过差分计算消耗**，不能直接相加。
2. **表计复位、换表必须保存事件**：
   - 复位/归零：差分结果为负时，判定为复位事件，按事件记录的基准值续算，**不产生负消耗**。
   - 换表：记录旧表终止读数与新表起始读数，跨表区间按事件拼接。
3. **倍率与单位有版本**：CT/PT 倍率、单位换算随时间的变更必须留版本，
   历史汇总按当时的倍率重算，不追溯篡改。
4. **重复、迟到数据可重算相关汇总**：
   - 重复数据（同消息 ID / 同设备+测点+设备时间）**入库去重**；
   - 迟到数据到达后触发受影响区间的汇总重算。
5. **汇总任务可重复执行而不重复累计**：汇总按「区间覆盖写」实现（幂等重算），
   不是「增量累加」。重复执行结果一致。
6. **父子表不重复加总**：存在总表-分表关系时，只按约定层级汇总，避免同一电量被计两次。
7. **分时价格跨时段且采样不足时**，采用**明确的分摊方法并标注估算**，
   不把估算值伪装成实测值。
8. **不同液体介质与不同量纲不混加**：水（m³）、电（kWh）、气（m³/Nm³）、液（L/t）
   各自独立汇总，禁止把 m³ 与 kg 无条件统一换算（面料「米/公斤」同理，见 `docs/data-model.md`）。
9. **不默认自动控制设备启停**：平台只做计量、分析与建议，
   调度建议与执行记录分离（任务书 10.11）。

## 三、精度与类型

- 能源读数按**仪表精度**定义 `DecimalField`，不使用 `float`。
- API 输出遵循 `docs/api-conventions.md`：Decimal 一律字符串。
- 累计值差分、倍率乘算在服务层保持全精度，仅在最终落库前按仪表精度做一次 `ROUND_HALF_UP`。
- 缺失数据或分母为零时，单耗类指标显示**「无法计算」**，不伪造数值。

## 四、汇总层级

```text
分钟汇总 → 小时汇总 → 日汇总 → 月汇总 → 年汇总
```

- 每层汇总可独立重算，且**标注数据来源与最后更新时间**。
- 原始数据保存周期可配置；归档清理**必须有审计**。
- 初期使用 MySQL 普通表 + 合理索引。**不盲目分区**：MySQL 分区与唯一约束、外键存在设计限制，
  采用前必须验证兼容性；数据量增长后再评估专用时序存储。

## 五、告警

```text
采集 → 校验 → 汇总 → 阈值判断 → 报警 → 确认 → 处理 → 关闭
```

- 告警类型：越限、离线、单耗异常、总量异常。
- **告警去重**：同一测点同一类型在窗口内只产生一条活动告警，恢复后再重新计数（对应必测案例 17）。
- 离线告警基于「最后接收时间」与配置的心跳周期判定。
- 阈值、离线判定参数可配置，变更留痕。

## 六、网络边界

- **默认只读采集**。
- 不把数据库或工控设备直接开放到互联网；采集网络与办公访问按实际网络条件隔离。
- 远程访问使用受控通道。
- **不在平台中下发安全逻辑修改**（不替代 PLC 实时控制、安全联锁、SIS 或消防联动，任务书 2.3.3）。

1. 独立可配置模拟器；

3. 设备独立凭证；

## 八、本轮实现的口径（阶段 5，代码位置 `apps/ems`）

> 本节描述**已经实现并有用例覆盖**的算法；上面 §一~§七 是设计口径，如与本节冲突以本节为准。
> 用例见 `backend/tests/test_ems_api.py`。

### 8.1 用量

```text
用量 = (本次读数 − 上次读数) × 仪表倍率
```

| 规则 | 实现 |
| --- | --- |
| 首次抄表（没有上次读数） | 用量记 **0**（不把表底值当用量） |
| 读数回退（本次 < 上次） | 直接拒绝，错误码 `READING_ROLLBACK`，提示上次读数；换表 / 清零请新开仪表 |
| 负读数 | 拒绝，错误码 `READING_NEGATIVE` |
| 倍率 | `EnergyMeter.multiplier`，数据库约束必须 > 0 |
| 精度 | 用量 6 位小数（`QUANTITY_QUANT`），金额 4 位小数（`MONEY_QUANT`），全部 `Decimal`，禁止 float |
| 抄表时间 | 默认业务当前时间；用量取「不晚于本次时间」的最近一条读数做差 |

### 8.2 计价

```text
费用 = Σ(各时段用量 × 该时段的生效单价)
```

- 价格解析 `resolve_price(company, medium, on_date, tariff_period)`：
  取该介质 + 该时段下 `effective_from <= 抄表日`、且（`effective_to` 为空或 `>= 抄表日`）的记录，
  多条时取 `effective_from` 最新的一条。
- **未维护单价时费用记 0**，并在报表行上标记 `priced = false`，页面显示「未维护单价」——
  不猜价格、不用默认价。
- 分时段（尖 `sharp` / 峰 `peak` / 平 `flat` / 谷 `valley`）**靠在抄表时选择时段**实现，
  平台不做电表内部的时段解析。
- 报表按**日 / 月 / 年**聚合，并支持尖峰平谷分时段明细（`peak_valley_rows`）。

### 8.3 运行记录与单耗

```text
运行时长（分钟） = 结束时间 − 开始时间
能耗 = 该仪表在「开始时间 ~ 结束时间」内抄表用量之和（也可手工指定）
单耗 = 能耗 ÷ 产量
```

- 产量为 0 时单耗记 0，且**不触发**单耗报警（没有产量就没有单耗口径）。
- 同一仪表**只允许一条未结束**的运行记录（`RUN_ALREADY_OPEN`）。
- 取消运行记录必须写原因（`RUN_REASON_REQUIRED`）。

### 8.4 报警触发路径与去重

| 报警类型 | 触发路径 |
| --- | --- |
| 越限报警 `over_limit` | 抄表写入后按阈值评估：读数 > `upper_limit` 或 < `lower_limit` |
| 设备离线 `offline` | 离线扫描：`last_reading_at` 早于 `now − offline_minutes`（或从未抄表）；触发后把仪表置为「离线」 |
| 单耗报警 `unit_consumption` | 运行记录结束：`unit_consumption > unit_consumption_limit` |
| 能耗报警 `energy_consumption` | 由 `raise_alarm` 服务承载（当前自动路径未接入，可人工上报） |

- **去重窗口**：同 `company + 仪表 + 报警类型 + 同一天` 只生成一条，重跑扫描 / 连续抄表不会刷屏。
- 关闭报警必须填写处理说明（`ALARM_NOTE_REQUIRED`）；状态只能由 `handle` / `close` 动作推进。
- 阈值匹配规则：指定仪表的阈值 + 该介质的通用阈值（`meter` 为空）同时生效。
