# 需求说明与范围（docs/requirements.md）

> 本文档是任务书的**范围基线**。逐条需求的可追溯记录见 `docs/requirements-matrix.md`，
> 阶段验收结论见 `docs/acceptance.md`。若两者冲突，以需求追踪矩阵为准。

## 一、平台定位（不可偏离）

意尚智造集成平台是**服饰企业内部业务平台**，直接实现采购、销售、生产、仓储、质量、
设备、能源等业务，**不是对接外部 ERP/MES/WMS 的接口平台**。

「集成」指：功能集成、数据集成、流程集成、权限集成、报表集成、设备数据接入。

## 三、明确排除（任务书 2.3）

1. **不开发**完整总账、税务申报、工资核算。
2. **不自研**杀毒引擎。
3. **不替代** PLC 实时控制、安全联锁、SIS 或消防联动。
4. 未获得协议与现场条件前，**不直接控制** AGV、吊挂设备等硬件。
5. **不宣称**辅助管理记录自动满足全部法规要求。
6. 不默认开发 SaaS 多租户计费平台（**首版为单企业、多工厂、多部门**）。
7. 第一版**不采用**微服务、Kubernetes 或复杂数据平台。
8. **不将真实硬件未接入作为业务系统无法开发的理由**——业务系统照常实现，
   设备接入在协议确认后补充。

## 四、阶段 0 与阶段 1 交付范围（本轮）

### 阶段 0（工程与基线）

- 仓库检查、需求追踪矩阵、架构 / 数据模型 / 权限文档。
- Vue 3 + TS 与 Django 5.2 + DRF 工程初始化。
- MySQL / Redis / 对象存储 / Compose 配置。
- 自定义 User 模型（**首次迁移即启用**）。
- 初始化与演示数据命令。
- 迁移、测试、检查、构建全部执行。

### 阶段 1（登录到主数据维护闭环）

- 会话登录（CSRF、退出、改密、个人中心）、登录限流与失败锁定。
- 角色、权限点、菜单、**数据范围（四层权限）**。
- 公司、部门、工厂、车间、线体、工位、员工、班次、班组。
- 物料分类、物料、面料属性、款式、颜色、尺码、SKU、计量单位与换算、标识。
- 仓库、库区、储位。
- 基础审批（模板、顺序多级、条件路由、提交/通过/驳回/撤回、快照与轨迹）。
- 审计日志、登录记录、通知、字典、编码规则、附件。
- 后台布局、菜单、工作台看板、实施进度页。

**阶段 1 明确不含**：库存余额与流水（阶段 2）、任何单据（销售/采购/生产）。
因此阶段 1 **不存在**「所有收货直接可销售」这类越权设计——因为尚无收货功能。

> **阶段 2 核心已补齐**：库存余额与只追加流水、库存单据、质量放行、幂等与并发安全已实现
> （`docs/inventory-rules.md` §八）。当前仍**不存在**「所有收货直接可销售」的设计：
> 收货默认进入**待检**库存，必须经过质量放行才能被领用或销售。

## 五、非功能要求

| 项 | 要求 |
| --- | --- |
| 数据持久化 | 所有业务数据真实落库，不使用内存或静态数据 |
| 后端校验 | 所有关键操作在后端校验，前端隐藏按钮不算授权 |
| 事务 | 关键服务使用 `transaction.atomic()`，必要时 `select_for_update()` |
| 数值 | 金额与库存禁用 float；Decimal 以字符串输出（见 `docs/data-model.md`） |
| 审计 | 关键操作与业务数据**同事务**保存 |
| 时区 | 存储 UTC，界面 `Asia/Shanghai`，测试跨日/跨月边界 |
| 权限 | 列表、详情、修改、审批、关联选择、导出、附件、图表**全部**校验 |
| 幂等 | 库存过账、扫码报工、转单、设备上报支持幂等 |
| 并发 | 并发用例必须使用真实独立事务与连接 |
| 代码质量 | Ruff 通过、TypeScript 类型检查通过、前后端构建成功 |
| 测试 | 关键数据库测试必须运行在 **MySQL**，不仅 SQLite |

## 六、演示与初始化数据（任务书 15）

- 2 个工厂，多个车间/线体/工位；6 个款式及其颜色尺码与 SKU；
  原辅料、包装、备件；原料/成品/备件仓；客户与供应商；不同岗位账号；
  采购/销售/生产与库存单据；质量异常；设备保养维修；模拟传感器/水表/电表；
  投诉与安全隐患；完整订单链路。
- 管理命令：`bootstrap_system`、`seed_demo`、`reconcile_inventory`、`rebuild_energy_summary`。
- 要求：命令具备**重复执行保护**；`seed_demo` **禁止在生产环境执行**；
  生产管理员通过安全初始化流程设置密码；**不在代码中硬编码公开管理员密码**；
  演示数据与真实采集来源明显区分。

> 阶段 0/1 已实现 `bootstrap_system` 与 `seed_demo`（含生产环境拒绝与幂等保护）；
> `reconcile_inventory`（阶段 2）、`rebuild_energy_summary`（阶段 5）随对应模块交付。

## 七、完成标准（任务书 19.3）

只有**同时**满足以下条件才算完成：页面可操作、API 可访问、数据持久化、权限生效、
状态迁移正确、异常处理明确、关键操作可审计、跨模块结果正确、自动化测试**实际执行**、
文档已更新、未完成内容明确列出。

**「页面已存在」不等于「已通过阶段验收」。** 未执行的测试必须标注「未执行」，不得写成通过。
